# AIOS Release v1.1.0

**Date:** 2026-05-10  
**Type:** Conceptual documentation release  
**Status:** Ready for review

## Summary

This release consolidates the AIOS documentation architecture after a broad structural, editorial and governance revision.

It formalizes the separation between:

- **AIOS** as the sovereign orchestrator;
- **FOCUS** as the cognitive protocol;
- **Personas** as domain authorities;
- **Human judgment** as the final decision layer.

## Release Rationale

This release is classified as `v1.1.0` because it introduces meaningful documentation and governance improvements without changing the constitutional foundation of the system.

It does not redefine the AIOS constitution, but it improves the repository structure, restores missing personas, increases consistency and introduces validation mechanisms.

## Major Changes

### 1. Core Architecture

- Created `docs/core/AIOS.md` as the canonical description of the AIOS orchestrator.
- Removed AIOS from the personas layer.
- Reinforced the distinction between orchestrator, protocol and personas.

### 2. Protocol Layer

- Moved FOCUS to the canonical path `docs/protocols/focus-protocol.md`.
- Removed the duplicate root-level `FOCUS.md` file.
- Added `docs/protocols/README.md`.

### 3. Personas Layer

- Restored missing personas:
  - AILIB
  - KNOW
  - KOGN
  - KHELP
  - SOUL
- Expanded legacy persona descriptions.
- Equalized persona depth across the ecosystem.
- Normalized language in PT-BR with full accentuation.
- Updated `docs/personas-index.md`.
- Expanded `docs/aios-persona-map.md`.

### 4. Templates and Governance

- Added `docs/templates/persona-template.md`.
- Added `docs/personas/README.md`.
- Added `docs/core/README.md`.
- Added `docs/LINK_INTEGRITY_CHECKLIST.md`.

### 5. Validation

- Added `scripts/validate_aios_docs.py`.
- Added `.github/workflows/validate-aios-docs.yml`.
- The validation workflow checks required files, persona links, required persona sections, map consistency and basic editorial normalization.

- This file documents the release conceptually. A Git tag named `v1.1.0` should still be created manually in GitHub if a formal repository tag is desired.
- The validation script is intentionally lightweight and focused on documentation integrity, not semantic quality scoring.
